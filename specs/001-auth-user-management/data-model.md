## Database Schema

### Table: `users`

Stores core user account information including credentials and profile data.

**Drizzle Schema Definition**:

```typescript
import { pgTable, uuid, varchar, timestamp, pgEnum } from 'drizzle-orm/pg-core';

// Enums for background levels
export const softwareBackgroundEnum = pgEnum('software_background', [
  'Beginner',
  'Intermediate',
  'Advanced',
  'Expert',
]);

export const hardwareBackgroundEnum = pgEnum('hardware_background', [
  'No Experience',
  'Basic Knowledge',
  'Hands-on Experience',
  'Professional Experience',
]);

export const users = pgTable('users', {
  // Primary key - UUID for better distribution
  id: uuid('id').primaryKey().defaultRandom(),

  // Authentication credentials
  email: varchar('email', { length: 255 }).notNull().unique(),
  password_hash: varchar('password_hash', { length: 255 }).notNull(),

  // Profile information (optional fields)
  software_background: softwareBackgroundEnum('software_background'),
  hardware_background: hardwareBackgroundEnum('hardware_background'),

  // Timestamps
  created_at: timestamp('created_at').notNull().defaultNow(),
  last_login_at: timestamp('last_login_at'),
});
```

**SQL Schema** (generated by Drizzle):

```sql
-- Create enums
CREATE TYPE software_background AS ENUM (
  'Beginner',
  'Intermediate',
  'Advanced',
  'Expert'
);

CREATE TYPE hardware_background AS ENUM (
  'No Experience',
  'Basic Knowledge',
  'Hands-on Experience',
  'Professional Experience'
);

-- Create users table
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  software_background software_background,
  hardware_background hardware_background,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  last_login_at TIMESTAMP,

  -- Indexes for performance
  CONSTRAINT email_valid CHECK (email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}$')
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_created_at ON users(created_at DESC);
```

**Field Descriptions**:

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `id` | UUID | No | Primary key, auto-generated |
| `email` | VARCHAR(255) | No | User email address (unique, case-insensitive) |
| `password_hash` | VARCHAR(255) | No | Bcrypt/Argon2 hashed password (managed by better-auth) |
| `software_background` | ENUM | Yes | User's software experience level |
| `hardware_background` | ENUM | Yes | User's hardware experience level |
| `created_at` | TIMESTAMP | No | Account creation timestamp (UTC) |
| `last_login_at` | TIMESTAMP | Yes | Last successful login timestamp (UTC) |

**Constraints & Validation**:
- Email must be unique (case-insensitive via PostgreSQL collation)
- Email format validated by CHECK constraint
- Password hash minimum 60 characters (bcrypt requirement)
- Background fields optional (can be null)

### Table: `sessions`

Stores active user sessions for authentication state management.

**Drizzle Schema Definition**:

```typescript
import { pgTable, uuid, varchar, timestamp, text } from 'drizzle-orm/pg-core';

export const sessions = pgTable('sessions', {
  // Primary key
  id: uuid('id').primaryKey().defaultRandom(),

  // Foreign key to users
  user_id: uuid('user_id')
    .notNull()
    .references(() => users.id, { onDelete: 'cascade' }),

  // Session token (hashed for security)
  token_hash: varchar('token_hash', { length: 255 }).notNull().unique(),

  // Session lifecycle
  expires_at: timestamp('expires_at').notNull(),
  created_at: timestamp('created_at').notNull().defaultNow(),

  // Audit information
  ip_address: varchar('ip_address', { length: 45 }), // IPv6 support
  user_agent: text('user_agent'),
});
```

**SQL Schema**:

```sql
CREATE TABLE sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash VARCHAR(255) NOT NULL UNIQUE,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  ip_address VARCHAR(45), -- Support IPv4 (15 chars) and IPv6 (45 chars)
  user_agent TEXT,

  -- Indexes for performance
  CONSTRAINT expires_at_future CHECK (expires_at > created_at)
);

CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_sessions_token_hash ON sessions(token_hash);
CREATE INDEX idx_sessions_expires_at ON sessions(expires_at);
```

**Field Descriptions**:

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `id` | UUID | No | Primary key, auto-generated |
| `user_id` | UUID | No | Foreign key to users.id (CASCADE delete) |
| `token_hash` | VARCHAR(255) | No | Hashed session token (unique) |
| `expires_at` | TIMESTAMP | No | Session expiration time (UTC) |
| `created_at` | TIMESTAMP | No | Session creation time (UTC) |
| `ip_address` | VARCHAR(45) | Yes | Client IP address (for audit) |
| `user_agent` | TEXT | Yes | Client user agent string (for audit) |

**Constraints & Validation**:
- User ID references users table with CASCADE delete
- Token hash must be unique
- Expires_at must be in the future (CHECK constraint)
- IP address max 45 characters (IPv6 support)

**Session Lifecycle**:
1. Created on successful sign-in (expires_at = now + 7 days)
2. Validated on each request (check token_hash + expires_at)
3. Updated every 24h (better-auth refreshes token)
4. Deleted on sign-out or expiration

### Table: `auth_events` (Optional - Audit Log)

Stores authentication-related events for security monitoring and debugging.

**Drizzle Schema Definition**:

```typescript
import { pgTable, uuid, varchar, timestamp, jsonb, pgEnum } from 'drizzle-orm/pg-core';

export const authEventTypeEnum = pgEnum('auth_event_type', [
  'signup_success',
  'signup_failed',
  'signin_success',
  'signin_failed',
  'signout',
  'session_expired',
  'rate_limit_exceeded',
]);

export const authEvents = pgTable('auth_events', {
  // Primary key
  id: uuid('id').primaryKey().defaultRandom(),

  // Foreign key to users (nullable for failed attempts)
  user_id: uuid('user_id').references(() => users.id, { onDelete: 'set null' }),

  // Event details
  event_type: authEventTypeEnum('event_type').notNull(),

  // Audit information
  ip_address: varchar('ip_address', { length: 45 }).notNull(),
  user_agent: varchar('user_agent', { length: 500 }),

  // Event metadata (error messages, additional context)
  metadata: jsonb('metadata'),

  // Timestamp
  created_at: timestamp('created_at').notNull().defaultNow(),
});
```

**SQL Schema**:

```sql
CREATE TYPE auth_event_type AS ENUM (
  'signup_success',
  'signup_failed',
  'signin_success',
  'signin_failed',
  'signout',
  'session_expired',
  'rate_limit_exceeded'
);

CREATE TABLE auth_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE SET NULL,
  event_type auth_event_type NOT NULL,
  ip_address VARCHAR(45) NOT NULL,
  user_agent VARCHAR(500),
  metadata JSONB,
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_auth_events_user_id ON auth_events(user_id);
CREATE INDEX idx_auth_events_type ON auth_events(event_type);
CREATE INDEX idx_auth_events_created_at ON auth_events(created_at DESC);
CREATE INDEX idx_auth_events_ip_address ON auth_events(ip_address);
```

**Field Descriptions**:

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `id` | UUID | No | Primary key, auto-generated |
| `user_id` | UUID | Yes | Foreign key to users.id (SET NULL on delete) |
| `event_type` | ENUM | No | Type of authentication event |
| `ip_address` | VARCHAR(45) | No | Client IP address |
| `user_agent` | VARCHAR(500) | Yes | Client user agent string (truncated) |
| `metadata` | JSONB | Yes | Additional event context (errors, etc.) |
| `created_at` | TIMESTAMP | No | Event timestamp (UTC) |

**Event Types**:
- `signup_success`: New user account created
- `signup_failed`: Registration attempt failed (validation, duplicate email)
- `signin_success`: User authenticated successfully
- `signin_failed`: Login attempt failed (invalid credentials)
- `signout`: User signed out
- `session_expired`: Session reached expiration time
- `rate_limit_exceeded`: Too many auth attempts from IP

**Metadata Examples**:
```json
// signup_failed
{
  "email": "user@example.com",
  "reason": "duplicate_email"
}

// signin_failed
{
  "email": "user@example.com",
  "reason": "invalid_credentials"
}

// rate_limit_exceeded
{
  "endpoint": "/api/auth/signin",
  "attempts": 6,
  "window_start": "2026-01-04T10:00:00Z"
}
```

## Validation Rules

### Email Validation

```typescript
const emailSchema = z
  .string()
  .email('Invalid email format')
  .max(255, 'Email too long')
  .toLowerCase()
  .trim();

// Additional server-side validation
function isDisposableEmail(email: string): boolean {
  const disposableDomains = ['tempmail.com', 'guerrillamail.com', /* ... */];
  const domain = email.split('@')[1];
  return disposableDomains.includes(domain);
}
```

### Password Validation

```typescript
const passwordSchema = z
  .string()
  .min(8, 'Password must be at least 8 characters')
  .max(128, 'Password too long')
  .regex(/[A-Z]/, 'Must contain at least one uppercase letter')
  .regex(/[a-z]/, 'Must contain at least one lowercase letter')
  .regex(/[0-9]/, 'Must contain at least one number');

// Password strength estimation (optional)
function estimatePasswordStrength(password: string): 'weak' | 'medium' | 'strong' {
  const hasUpperLower = /[A-Z]/.test(password) && /[a-z]/.test(password);
  const hasNumbers = /[0-9]/.test(password);
  const hasSpecial = /[^A-Za-z0-9]/.test(password);
  const isLongEnough = password.length >= 12;

  if (hasUpperLower && hasNumbers && hasSpecial && isLongEnough) return 'strong';
  if (hasUpperLower && hasNumbers && password.length >= 8) return 'medium';
  return 'weak';
}
```

## Data Access Patterns

### Common Queries

```typescript
import { db } from './db';
import { users, sessions } from './schema';
import { eq, and, gt } from 'drizzle-orm';

// Find user by email
async function findUserByEmail(email: string) {
  return db
    .select()
    .from(users)
    .where(eq(users.email, email.toLowerCase()))
    .limit(1);
}

// Create new user
async function createUser(data: {
  email: string;
  password_hash: string;
  software_background?: string;
  hardware_background?: string;
}) {
  return db.insert(users).values(data).returning();
}

// Get user with active sessions
async function getUserWithSessions(userId: string) {
  return db
    .select({
      user: users,
      sessions: sessions,
    })
    .from(users)
    .leftJoin(sessions, eq(sessions.user_id, users.id))
    .where(
      and(
        eq(users.id, userId),
        gt(sessions.expires_at, new Date())
      )
    );
}

// Update last login timestamp
async function updateLastLogin(userId: string) {
  return db
    .update(users)
    .set({ last_login_at: new Date() })
    .where(eq(users.id, userId));
}

// Delete expired sessions (cleanup job)
async function deleteExpiredSessions() {
  return db
    .delete(sessions)
    .where(lt(sessions.expires_at, new Date()));
}

// Log authentication event
async function logAuthEvent(event: NewAuthEvent) {
  return db.insert(authEvents).values(event);
}
```

## Data Retention & Privacy

### GDPR Considerations

1. **Right to Access**: Users can request their data via profile page
2. **Right to Erasure**: Account deletion removes all user data (CASCADE)
3. **Data Minimization**: Only collect necessary fields (email, password, background)
4. **Purpose Limitation**: Background data used only for personalization
5. **Storage Limitation**: Auth events retained for 90 days (implement cleanup job)

### Retention Policy

```typescript
// Cleanup jobs (run daily)
async function cleanupExpiredSessions() {
  await db.delete(sessions).where(lt(sessions.expires_at, new Date()));
}

async function cleanupOldAuthEvents() {
  const ninetyDaysAgo = new Date();
  ninetyDaysAgo.setDate(ninetyDaysAgo.getDate() - 90);

  await db.delete(authEvents).where(lt(authEvents.created_at, ninetyDaysAgo));
}
```

## Performance Considerations

### Indexes

All critical query paths are indexed:
- `users.email` - Unique constraint + index (login lookups)
- `sessions.token_hash` - Unique constraint + index (session validation)
- `sessions.user_id` - Foreign key index (user sessions lookup)
- `sessions.expires_at` - Index (cleanup queries)
- `auth_events.created_at` - Index (audit queries)

### Query Optimization

- Use connection pooling (NeonDB Pool class)
- Implement query caching for frequently accessed data (user profiles)
- Use prepared statements (Drizzle handles this automatically)
- Limit auth_events queries with pagination

### Scalability

- Database can handle ~500 concurrent users (per spec SC-005)
- Session cleanup job prevents unbounded growth
- Auth events table may need partitioning at scale (future optimization)
